# QX 广告分析与过滤

根据真实流量选择影响范围最小的过滤方式，保留正常内容、响应协议和用户已有配置。按任务交付本地规则、响应脚本或可订阅资源，并说明验证范围。分析、编码或离线测试不自动包含发布、安装工具或修改设备配置。

## 确认目标与采集条件

- 确认 App 名称、版本、bundle ID 或网站域名，以及广告位置、触发动作和预期交付方式。区分同名客户端与不同发行版。
- 检查现有规则、重写与 MitM 状态、配置来源和脚本加载方式；修改配置前备份相关内容，保留证书、节点与其他分流。
- 采集网站请求、App 流量或处理配置同步时，读[采集与配置生效](references/capture.md)。需要操作 iOS 屏幕时，再读[iOS 设备控制](references/ios-device-control.md)。根据当前可用能力选工具，不要求固定设备或工具链。

## 从响应确定广告来源

将触发动作、画面与请求时间对齐，取得少量有代表性的广告、正常和错误响应。分别检查独立广告接口、共享内容接口、SDK 配置、预加载与实时投放；不要只在信息流里搜索广告标记。

根据字段含义、样本差异和渲染结果判断广告。正文中的“广告”、泛化的“推荐”标签、未经证实的数字值或 TLS 域名都不能单独成为删除依据。回归样本保留结构与类型，用假标识和示例素材重建，去除凭据与个人数据。

网站需区分网络广告请求与 HTML 节点；请求被拦截后仍可能保留 DOM 占位。仅在响应格式与页面结果可验证时改写 HTML。

App 加入 MitM 后加载失败且没有解密响应时，先检查证书信任与连接错误，排除采集通道问题。取得响应前不要猜测广告字段；不能可靠控制时，说明证据与限制，再确定后续范围。

## 选择过滤方式

| 已确认的接口特征 | 处理选择 |
| --- | --- |
| 纯广告接口，客户端可接受拒绝或空响应 | 选择已验证兼容的 QX 原生拒绝类型 |
| 广告接口需要特定成功状态或响应外壳 | 清理广告容器，保留协议外壳与错误语义 |
| 正常内容与广告混合 | 仅移除已确认的广告字段或记录，保留正常顺序、分页和元数据 |
| 预加载或本地缓存 | 先验证更新、覆盖和失效语义，再决定清空、保留记录标识或修改展示条件 |

URL 规则限定域名、路径和参数边界，覆盖实际查询参数顺序，检查旧规则冲突。不要为去除少量广告而封锁共享 API 或素材域名。广告标志、缓存时间和 SDK 开关的取值必须来自目标接口证据。

## 编写与验证脚本

先检查 URL、状态和类型，只解析需要处理的响应。错误响应、未知结构与无法解析的正文原样放行。保留已确认的 JSONP 包装或 SDK 后缀，不任意截断正文来凑出 JSON。

用[验证与离线测试器](references/verification.md)构造正反样本，检查过滤结果、正常字段、URL 边界和回调行为。自带测试器适用于不含诊断 I/O 的同步响应脚本，不模拟完整 QX 环境。

开屏验证应有可复现广告的对照，并排除缓存与频控。区分文件已同步、目标规则已执行、广告已消失和正常功能未受损；单次没见广告或文件哈希相同不能替代运行验证。

## 按需部署与交付

交付订阅资源时，读[订阅资源格式](references/resource-format.md)：使用 QX 原生 rewrite resource，JS 独立托管，通过完整 HTTPS URL 引用。托管地址与版本来自当前任务，不绑定某个仓库、分支或目录布局。仅需本地规则时不引入远程发布流程。

正式过滤逻辑与临时诊断分开。交付前移除本次增加的观察规则、版本探针、统计、日志和采集代码，恢复为验证临时调整的间隔与开关。避免无意义的重复遍历，无改动时直接放行，仅在改写时编码；不把特定代码风格当作性能结论。

对最终版本运行相关回归。报告目标版本、实际验证方式、未验证范围与停用方法；订阅另附资源地址和发布状态。原始流量、账号、配置备份、节点与证书留在私有工作目录。

不确定的语法与 API 以 [QX 官方配置示例](https://github.com/crossutility/Quantumult-X/blob/master/sample.conf)和[响应脚本示例](https://github.com/crossutility/Quantumult-X/blob/master/sample-rewrite-with-script.js)为准。具体 App 的历史接口、设备操作结果与授权记录不作为通用前提。
