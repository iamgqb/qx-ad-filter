# 验证与离线测试器

## 离线验证的重点

为实际处理的接口准备脱敏广告响应、正常响应和错误响应，检查可观察行为：广告字段或记录如何变化，正常内容顺序与分页是否保留，未知结构是否放行，SDK 包装是否完整，以及 `$done` 是否恰好调用一次。URL 匹配需覆盖查询参数顺序、邻近路径和非目标域名，避免过宽或漏匹配。

精简已有脚本时，可在私有工作目录将旧版作为行为对照。最终测试不应依赖个人目录、完整配置或旧排查脚本，需能在干净仓库中运行。

## 通用同步回调测试器

技能自带 `scripts/run-rewrite.cjs`，适用于不含日志、持久化、通知和额外网络操作的同步响应过滤脚本。只需 Node.js 18+，无 npm 依赖：

```sh
node <技能目录>/scripts/run-rewrite.cjs <待测脚本.js> <用例.json>
```

用例文件是数组，每项包含 `name`、`input` 和 `expected`：

```json
[
  {
    "name": "独立广告数组被清空",
    "input": {
      "url": "https://api.example.com/ads",
      "statusCode": 200,
      "body": {"ads": [{"id": "fixture-ad"}], "ok": 1}
    },
    "expected": {"mode": "json", "body": {"ads": [], "ok": 1}}
  }
]
```

`input.body` 的对象或数组会被编码成响应正文，字符串按原始正文传入。`statusCode` 默认 200，`method` 默认 `GET`；可选的 `requestHeaders` 和 `responseHeaders` 用于需要请求头或响应头的场景。预期模式：

- `passthrough`：回调返回空对象。
- `json`：回调的 body 按 JSON 比较，忽略对象属性的书写顺序。
- `text`：回调 body 精确匹配，用于 SDK 后缀、HTML 等。

测试器要求同步完成、恰好一次回调，并拒绝日志、持久化、通知及额外网络操作。它会返回 JSON 解析/编码次数，便于测试调用方检查未修改时零编码、修改时一次编码。CLI 只打印用例名和通过或失败，不输出正文。

它只用于执行可信的待测代码，不是安全隔离环境；不支持异步请求、计时器、完整 QX API 或 JavaScriptCore 的兼容性模拟，也不判断 QX 规则是否命中。实际设备验证需单独完成。

## 实机或浏览器验证

需要订阅交付时，按[订阅资源格式](resource-format.md)检查格式、托管路径与发布状态。配置和脚本同步则按[采集与配置生效](capture.md)确认实际加载来源。

将以下证据分开记录：

1. **命中与数据**：目标请求进入预期规则，处理后的字段符合预期。必要时使用短暂的诊断标记；最终移除。
2. **画面与正常功能**：在相同触发动作下广告不再出现，正常内容、刷新、翻页或页面渲染仍正常。

开屏先记录能复现广告的对照，再检查频控、预加载更新时间、缓存记录 ID 和启动/恢复路径。自然间隔未到时，连续启动没有广告不能证明修复。若已有明确投放间隔，可选择等待自然间隔，或在当前授权范围内临时缩短间隔做诊断对照；这种修改必须恢复，不能进入最终版本。

记录帧的相对时间和观察窗口。OCR 的“广告/跳过”识别只能辅助筛查，还需查看代表帧，避免把未加载、错误页或遮挡误当成成功。

## 最终清理

移除本次增加的观察规则、临时脚本引用和不再需要的同名别名，恢复测试期间修改的间隔及开关。正式代码中删除仅服务于诊断的统计计算、分页快照、记录写入和调试日志，不能仅关闭写入而保留无用计算。对最终清理后的版本运行相关回归。

基于引用和用途清理本次生成的文件；不要按目录名推断其中全部数据都是临时日志，其他规则可能依赖这些文件。原始证据、配置备份和诊断样本不进入发布目录。

报告哪些是实际设备观察、哪些是离线测试、哪些仅完成文件同步。未复现广告或未确认目标规则执行时，明确保留验证状态，不宣布彻底解决。文件大小缩减不能作为 CPU 或耗电下降的测量结果。
