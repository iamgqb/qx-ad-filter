# 采集与配置生效

## 选择采集路径

先检查已有的浏览器工具、代理请求记录、连接器和本机 CLI，使用能取得目标响应的路径。

| 目标与现有证据 | 采集方式与边界 |
| --- | --- |
| 网站 | 关联页面广告元素、触发动作与 Network、HAR 或代理记录，区分独立请求、共享 API 和 HTML 内容 |
| 原生 App | 记录版本与 bundle ID，按广告场景采集冷启动、恢复前台、刷新或翻页；使用已可用的 QX 解密响应或其他授权采集通道 |
| 只有连接信息 | 按目标进程与时间筛选 pcap 或域名时间线，用于缩小候选范围，不能据此推断完整 URL、响应字段或广告性质 |

加入 MitM 后 App 加载失败且观察器无响应时，对照未加入解密域名时的行为，检查连接和证书信任错误。不要把“尚未取得响应”当成“响应没有广告”。仅凭域名或单个错误不能确定客户端的具体证书校验实现。

## 采样与脱敏

临时观察脚本与正式过滤器分开。采集量以识别接口结构和构造回归为限；如需持久记录，设置采样上限、固定覆盖或有限条数。

长期保留方法、路径、字段类型和必要的脱敏摘要。HAR、查询参数、请求头、响应正文与界面树都可能含凭据；清理 Cookie、Authorization、令牌与账号标识，再生成可分享材料。回归数据用假标识和示例素材重建，原始流量放在项目外私有目录。

连续截图需记录每帧相对触发时间，覆盖广告展示窗口；抓包按目标进程筛选并限制时长。使用设备 CLI 前核对本机版本与 `--help`，不要直接依赖库内部 API 或旧任务的命令参数。

## 设备操作的能力边界

分别验证发现设备、启动或终止 App、截图、读取控件、点击和解锁的能力。能启动或读屏不代表能点击；基础 USB 通道不能点击也不代表其他已配置通道不可用。CoreDevice ID 与配对 UDID 可能不同，应按当前工具发现结果使用；文件共享可用不代表可以读取 App 的全部容器或 iCloud 文件。

需要重载配置、切换 VPN 或连续触发 App 时，读 [iOS 设备控制](ios-device-control.md)，优先复用已有且在当前授权内的控制通道。不要为采集默认引入开发签名 App、设备注册或系统安全设置变更。

若锁屏或工具能力确实阻断必要操作，先准备好采集，再给用户一个明确的手动步骤；不索要锁屏密码。一次动作未生效且已发现能力限制后，改用可行路径，避免重复无效操作。

## 确认配置来源与副本

辨明当前使用的是手机本地配置、iCloud 文档、iCloud Link 还是远程资源，以及脚本来自文件共享、iCloud 或远程 URL。同名文件不代表同一加载来源。

修改配置前备份，更新任务涉及的规则和必要 hostname，核对证书、节点与其他分流未被意外改变。对于有身份跟踪或同步语义的文档，优先使用原生配置流程或保留文件身份的写入方式。

## 分层检查生效状态

| 状态 | 可用证据 | 仍需确认 |
| --- | --- | --- |
| 文件已同步 | 从实际目标位置回读，比较内容或哈希 | 运行时是否使用该副本 |
| 配置已重新应用 | 当前配置来源正确，更新流程完成且无可见错误 | 请求是否进入新规则 |
| 隧道已恢复 | 界面或系统状态显示已连接 | 连接状态不能证明规则版本 |
| 新规则已执行 | 目标请求与处理结果对应，必要时用临时版本标记 | 广告画面与正常功能是否符合预期 |

根据实际加载方式刷新资源、脚本或重新应用配置；只在需要时重启隧道。区分同步延迟、资源缓存和规则未应用，不以重新打开 App 或刷新资源列表作为全部完成的证据。结束后移除临时标记与重复观察规则。
