# 恩基爱社区 iOS：广告 SDK 过滤与实机验证

2026-10-25，在 iPhone 12 / iOS 18.6.2、恩基爱社区 1.1.47（`com.enjiai.sign`，build `10.1.47`）、Quantumult X 1.8.1 上编写并安装了 [nga-ad-filter.conf](../../rewrites/nga-ad-filter.conf) 1.0.0。资源包含 5 条原生 `reject-dict` 规则和 7 个 MitM hostname，无 JavaScript、日志、存储、通知或额外网络请求。

## 可复用经验

- 广告 SDK 可能存在聚合与回退渠道，单独封锁一个候选接口后仍需检查实际投放请求。
- 定位接口时，限量采集路径、字段名等元数据有时已足够；不必为每个候选请求保存完整正文。
- 类似 `adfree` 的字段名和真实改写命中都不能证明广告已关闭，处理决策仍需数据与画面对照。
- 独立广告接口可优先尝试兼容的原生拒绝，保留 SDK 配置和业务路径；共享 SDK 接口的影响可能超出目标 App。
- 用停用后复现广告、再启用后观察画面的对照增强证据，同时保留频控窗口和未回归场景的边界。

以下接口、采样上限和截图时点来自本轮分析，不作为其他目标的固定参数。

## 过滤依据

冷启动、恢复前台和推荐流中曾多次出现带广告标记的淘宝、天猫及快手 SDK 广告。只拦截独立广告接口，保留 NGA 的普通帖子、图片、活动和评分接口。

在当时任务授权范围内，临时解密 14 个已在 `NGA_Pro` 进程连接中出现的 SDK 候选域名。观察器设定最长 5 分钟、最多 55 条，达到上限后停止；共取得 19 种请求路径。记录仅包括域名与路径、查询参数名、请求方法、状态码、响应长度和 JSON 字段名，没有保存正文、请求头、账号或查询参数值。

| 已确认的请求 | 结构或用途证据 | 正式处理 |
| --- | --- | --- |
| `g1.tagtic.cn/v3/ad/aggregation` | 广告聚合接口，成功响应包含 `result`、`message`、`data` | 原生拒绝 |
| `mi.gdt.qq.com/gdt_mview.fcg`、`v2mi.gdt.qq.com/gdt_mview.fcg` | 响应包含 `ret`、`reqinterval`、`last_ads` 和按广告位组织的 `data` | 原生拒绝 |
| 穿山甲 `/api/ad/union/sdk/get_ads/`、`/api/ad/union/mediation/exchange/` | 实际投放或交换路径，部分响应包含 `request_id`、`status_code`、`reason` | 原生拒绝 |
| `open.e.kuaishou.com/rest/e/v3/open/univ` | 响应包含 `impAdInfo`、`adGlobalConfigInfo`、`hasAd` 等广告字段 | 原生拒绝 |
| `adservice.sigmob.cn/ad/v4` | 实际投放路径；正文不直接按 JSON 处理 | 原生拒绝 |

规则限定完整域名、具体路径和参数边界。SDK 的配置、统计与其他路径继续放行，不封锁整个域名，也不拦截共享图片域名。资源中的 hostname 负责 HTTPS 解密，URL 规则才决定是否拒绝。

## 实机验证

- 首次启用后，冷启动约 2、4.4、7.5、12.4 秒连续截图；约 7.5 秒已显示正常推荐页，未出现此前的商业开屏。
- 推荐流向下滚动两屏，原 SDK 广告卡片未再出现，也未见广告空占位；普通帖子和图片继续显示。
- 热帖可切换「玩家生活」并加载正常列表；社区目录、网事杂谈列表、普通帖子正文和回复滚动正常。
- 最终版本下，活动、评分与资料页均可正常打开；关注页显示正常的空列表提示。
- QX Activity 中实际出现 `g1.tagtic.cn/v3/ad/aggregation` 的重写标记；同域下的策略请求仍有正常网络传输。此项用于区分“文件已同步”和“规则已命中”。
- 停用新增规则并恢复原配置后，再次冷启动；约 7.5 秒复现了带倒计时和广告标记的淘宝闪购开屏。
- 重新启用同一版本，再于约 2、4.5、7.4、12.4 秒截图；约 7.4 秒与 12.4 秒均显示正常推荐页，未见商业开屏。对照没有修改服务端频控或清空 App 数据。

以上是本轮版本和观察窗口内的结果，不代表覆盖所有投放、长时间频控或未来版本。关注页在当前账号下为空列表，未验证有关注内容时的表现。官方活动轮播、编辑推荐及普通帖子保留，不能只因内容涉及游戏推广而删除。

## 未采用的方案

用户资料响应 `app_api.php?__lib=user&__act=detail` 中存在 `result.adfree: 0`。临时改为 `1` 时记录到了真实改写命中，但随后仍出现商业开屏，因此没有交付该方案，也没有改写会员或账号的其他字段。

单独拒绝 `sdk.1rtb.net/sdk/req_ad` 和 `sdk.zhangyuyidong.cn/api/zysdk` 仍有广告回退；两条实验规则已移除。不可解析的 SDK 正文没有被强行截断或按猜测字段改写。

## 离线回归与交付

当时 `npm test` 共 26 项全部通过。新增回归检查原生资源格式、每个目标路径唯一匹配、查询参数顺序、MitM 覆盖、普通业务与相邻路径不误匹配，以及没有脚本或诊断依赖。离线测试不代替上述实机验证。

最初使用本地配置合并方式，核对配置相对备份仅新增正式规则和必要 hostname，其他内容保持一致；观察到重写、MitM 与 VPN 开启。随后按用户要求，将同一版本发布到仓库 `main` 分支，提供[远程重写资源](https://raw.githubusercontent.com/iamgqb/qx-ad-filter/main/rewrites/nga-ad-filter.conf)，并改用订阅获取规则。安装与停用方法见 [README](../../README.md#恩基爱社区订阅使用)，不依赖某个个人配置名、原有规则数量或特定注释标记。

这些 SDK 投放接口可能被其他 App 共用；其他 App 使用相同接口时，其广告也会被拦截。本轮没有回归其他 App。

## 采样收尾

临时观察配置已撤下，只保留正式资源所需的 hostname；观察脚本、元数据文件及本轮存储键均已移除并核对。正式资源没有诊断代码。原始连接采样、截图、私有配置备份及元数据副本不进入仓库。
