# 知乎 iOS：开屏、回答底部与 HTTPDNS 回退

2026-11-04 至 11-05，在 iPhone 12 / iOS 18.6.2、知乎 11.11.0（`com.zhihu.ios`，build `41110`）、Quantumult X 1.8.1 上分析开屏、推荐流与回答底部。首次交付的 1.0.0 仅处理开屏；[zhihu-ad-filter.conf](../../rewrites/zhihu-ad-filter.conf) 1.1.0 补充回答底部投放与必要的 HTTPDNS 回退，共 3 条原生 `reject-dict` 规则、1 个 MitM hostname，无 JavaScript。

## 可复用经验

- JSON 字段可能再次包含编码为字符串的 JSON，需要检查内层结构，不能把字符串直接当作不可解析的广告协议。
- 独立广告接口在客户端接受空字典时，可以使用原生拒绝；保留共享内容接口与素材域名。
- 客户端的内容卡片结构会变化。只有正常响应时，不把历史广告类型或数字值套到新结构上。
- 文件同步、规则命中与广告消失分别验证。iCloud 采集文件存在同步延迟，不能用未及时更新的副本判断请求没有发生。
- 开屏使用停用后复现、启用后观察的对照，并保留缓存和频控方面的边界。
- 应用内 HTTPDNS 可能同时使用单域名与批量查询。域名重写需结合新连接、实际查询边界和系统解析回退验证，不能只在首次启动时检查命中。

## 1.0.0 开屏请求与响应证据

先按知乎实际主进程采集少量连接，确认出现 `api.zhihu.com`、`appcloud2.zhihu.com` 等域名，再临时解密并采样。初期观察器限定最多 5 分钟、80 次响应；后期只对推荐接口补采，最多保存 6 份响应。原始正文、截图、界面树与配置备份保存在项目外私有目录。

| 接口 | 实际结构或用途 | 最终处理 |
| --- | --- | --- |
| `api.zhihu.com/commercial_api/launch_v2` | 外层包含 `app_float_video`、`float_layer`、`launch`；字段值为 JSON 字符串，内层包含 `ads` 数组；预加载样本的 `launch.ads` 有 27 条记录 | 原生 `reject-dict` |
| `api.zhihu.com/commercial_api/real_time_launch_v2` | `launch` 为 JSON 字符串，内层 `ads` 样本包含 4 条广告及素材、展示和点击跟踪字段 | 原生 `reject-dict` |
| `api.zhihu.com/topstory/recommend` | 外层有 `dataV1`、`data`、`styles`、`paging` 等；正常记录分别为 `sdui` 与 `ComponentCard`，样本中的内容类型为回答 | 原样保留 |
| 热榜、关注提示、正文、`commercial_api/sdk/prefetch` 和 `appcloud2.zhihu.com/v3/resource` | 普通业务或配置路径；未证实应整体拒绝 | 原样保留 |

最终正则只匹配两个已观察到的开屏路径，限定 HTTPS、完整域名、路径终点或查询参数边界。不拦截整个 `commercial_api`，也不封锁图片或 SDK 域名。

推荐流采样和连续滚动中未复现带广告标记的卡片，没有取得可用于确认广告记录的正样本，因此没有编写信息流删除脚本。正常的 `dataV1`、`data`、分页、样式及推荐内容均保持原样。

## 1.0.0 开屏实机对照

1. 未启用本次过滤时，冷启动约 2、5、8、12 秒连续截图；约 5 秒复现带“跳过”和“广告”标记的拼多多运动鞋开屏。
2. 启用精确原生拒绝后，以同样时点截图；约 5 秒和 12 秒显示正常推荐内容，未见此前的商业开屏。
3. QX Activity 筛选商业接口，实际看到 `launch_v2` 的重写标记，以及 `real_time_launch_v2` 的 `REWRITE / REJECT-DICT`。相邻横幅、下拉刷新与二楼路径仍有普通网络传输，未被该规则匹配。
4. 仅停用本次开屏规则，再次冷启动；约 5 秒、8 秒复现带倒计时及广告标记的拼多多汉服开屏，支持此前差异来自规则启停。
5. 发布后切换为远程订阅，再按约 2、5、8、12 秒记录冷启动；约 5 秒与 12 秒均显示正常推荐内容，未见商业开屏。普通回答正文、关注列表与热榜均可正常打开。

对照没有清空知乎数据，也没有改写投放间隔或账号字段。测试期间保留原有其他资源，未单独验证本资源对所有第三方 SDK 回退投放的覆盖。以上结果仅覆盖该版本与观察窗口，不代表所有缓存状态、长期频控或未来版本。

## 2026-11-05：回答底部广告与解析回退

用户反馈的现场位于普通回答末尾、评论之前，带“美数”和“广告”标记。后续同一位置还出现游戏与电商素材，不能只封锁某张图片。1.0.0 没有覆盖这个广告位。

按知乎进程限时采集连接，并对齐同一回答的重新进入动作。后期采样仅保留字段类型、数组长度和脱敏路径，最多 20 份、10 分钟，通过仅接收当前设备的局域网服务保存到项目外私有目录，不采集请求头、查询值或正文文案。

| 实测接口 | 证据与处理 |
| --- | --- |
| `api.zhihu.com/commercial_api/answer/数字ID/bottom-v2` | 解析 `adjson` 后包含 `ads`，正样本长度为 1，并有 `creatives`、广告展示和实验信息；新增精确 `reject-dict` |
| `api.zhihu.com/answers/v2/数字ID` | 独立的正文接口，包含作者、评论配置、问题、交互栏等正常字段；保留 |
| `http://182.61.194.7/v2/resolv` | 实测 `host=api.zhihu.com` 和以该域名开头的逗号分隔批量查询；仅拒绝这两类查询，触发系统解析回退 |

热启动期间，部分 API 连接不再显示域名解密；按进程采集到的明文 HTTPDNS 请求证实存在批量 `host` 参数，逗号编码为 `%2C`。仅处理单域名查询会遗漏批量请求。补充批量边界并冷启动后，QX 再次显示域名请求，且取得上述广告和正文结构。没有把公网 IP 加入 MitM；正式资源只解密 `api.zhihu.com`。

HTTPDNS 规则限定实测服务器、`/v2/resolv`、`host` 参数名和首个域名边界，兼容参数顺序与逗号编码，不拒绝其他域名的独立查询。同一批量查询中的其他域名也会回退系统解析；已验证搜索、正文和评论加载，不保证未来的解析服务器、查询顺序或 SDK 行为。它不是广告内容接口，而是维持本版本域名重写生效的配套措施。

启用前，同一回答末尾出现带广告标记的电商卡片；启用精确底部规则后，从相同搜索结果重新进入该回答，按相同路径滚动，相关搜索之后直接显示评论，广告卡片消失。QX Activity 中同一 `bottom-v2` 路径从正常传输变为 `REWRITE / REJECT-DICT`。正文尾部、内容专栏、相关搜索与评论保留。此结论覆盖本次实测回答广告位，尚未验证推荐流广告、其他广告位、全部第三方 SDK 回退或长期频控场景。

1.1.0 的 `npm test` 共 32 项通过，新增数字回答 ID、底部路径版本、HTTPDNS 参数顺序、批量分隔符及非目标解析边界回归。正式资源没有响应脚本，因此不创建占位 JS 或空样本文件。

临时观察规则、单独试验的解析规则及其脚本已移除，收敛为与正式资源相同的原生规则；未增加公网 IP 的解密范围、持久采样键或投放间隔改写。配置备份与原始证据保存在项目外私有目录。

资源 1.1.0 随提交 `6e4c743` 发布到 `main`。发布后核对同一 Raw URL，返回 HTTP 200、`text/plain; charset=utf-8`，513 字节与本地文件逐字节一致。QX 原生刷新后获取了包含开屏、回答底部与 HTTPDNS 的 3 条远程规则。

移除对应本地重复规则后，界面确认 3 条知乎规则均来自远程资源，本地只保留任务前已有规则；重写、MitM 和 VPN 均开启。关联配置回读与任务前相比仅更新该订阅名称，证书、节点、其他资源与分流保持原字节。仅使用远程订阅再次冷启动，约 2、5、9 秒未见开屏广告；重新搜索并进入原回答，按相同路径滚动到末尾，广告位消失，正文、相关搜索和评论正常。最后停留在该回答末尾。
